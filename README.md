# BITwiki V2

**Public MediaWiki source. Start here.**

BITwiki is the durable knowledge layer of the **BITwiki / BIThub / BITCORE** ecosystem.

This repository has two jobs:

1. hold the public V2 MediaWiki source;
2. preserve enough V1 source/provenance that V2 can be improved without erasing what came before.

## Repository map

```text
wiki-content/
├── Main/          ordinary public knowledge pages
├── BITwiki/       foundations, architecture, governance, guides
├── Portal/        high-level entry points into knowledge domains
├── Template/      reusable/transcluded wiki components
├── Property/      Semantic MediaWiki properties
├── Category/      editable category-page source for V2 navigation
└── archive-v1/    read-only V1 source/provenance archive
```

**Repository directories mirror MediaWiki page classes or archival transport. They are not the ontology.**

```text
namespace ≠ entity type ≠ domain ≠ Book Matter ≠ epistemic status ≠ relationship
```

## V1 archive: four different states

Do not treat these words as synonyms:

| State | Meaning |
|---|---|
| **accounted** | the V1 title/surface has a stable archive record and source reference |
| **archived** | exact raw source/revision data has been captured into Git |
| **reconciled** | related V1 versions were compared and their unique content/provenance understood |
| **refactored** | a deliberate V2 implementation exists |

Current archive surfaces:

- [`archive-v1/manifest.json`](archive-v1/manifest.json) — all **162 Main-namespace titles**.
- [`archive-v1/wiki-surface-manifest.json`](archive-v1/wiki-surface-manifest.json) — namespace and maintenance surfaces beyond Main.
- [`archive-v1/templates/manifest.json`](archive-v1/templates/manifest.json) — V1 Template-namespace titles observed during the reconstruction audit.
- [`archive-v1/categories/manifest.json`](archive-v1/categories/manifest.json) — category-index snapshot and category migration state.
- [`archive-v1/special/README.md`](archive-v1/special/README.md) — operational Special pages that must be checked during migration/maintenance.
- `archive-v1/raw-snapshots-*.md` — exact public wikitext already captured.

**Special pages are operational reports generated by MediaWiki. Archive their observations when useful; do not deploy them as ordinary V2 pages.**

## Default knowledge-page anatomy

Use only the matter the subject needs:

```text
identity / semantic metadata
Overview
Definition
Scope & importance
Core concepts / mechanism
Examples
Applications / implications
Epistemic notes
References
```

Mature pages may add history, frameworks, methods, evidence, case studies, controversies, timelines, primary/secondary sources, bibliography, knowledge maps, implementation, limitations, and related concepts.

**Modularity does not mean fragmentation.** Keep the parent page coherent. Split/transclude matter only when the portion is independently useful.

## Canon workflow

```text
source
→ preserve raw signal
→ compare revisions
→ research / cross-check
→ distill redundancy
→ revise
→ verify
→ canonicalize
→ transclude / relate
→ publish
```

A cleaner sentence is not automatically a better sentence. Preserve authored voice, unique distinctions, citations, provenance, and meaningful historical development.
